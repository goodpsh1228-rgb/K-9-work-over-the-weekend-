## 0. 진행 방식

- 아래 "9. 제작 순서"의 단계 번호대로 **한 단계씩만** 진행하고, 사용자의 확인을 받은 뒤 다음으로 넘어갑니다.
- 모든 화면과 안내 문구는 **한국어**입니다.
- 비밀 키(Supabase `service_role` 키, 비상 키 등)는 **채팅에 붙여넣지 않고** `.env` 파일에만 넣도록 안내합니다. `.env`는 GitHub에 올라가지 않게 `.gitignore`에 반드시 포함합니다.
- 실제 인원 명단은 **마지막 테스트가 끝난 뒤**에 등록합니다. 그 전에는 가짜 이름으로만 확인합니다.
- 규칙이 모호하거나 이 문서에 없는 결정이 필요하면, 임의로 정하지 말고 사용자에게 한 번에 하나씩 물어봅니다.

## 1. 프로젝트 개요

군 부대에서 주말·공휴일 출근자를 정하는 웹사이트입니다.

1. 인원들이 각자 휴대폰으로 접속해 근무일마다 **희망 / 미희망**을 표시하거나 **휴가·부상(제외)** 기간을 입력합니다.
2. 마감 시각이 되면 자동으로 추첨합니다. 희망자가 우선이고, 자리가 남으면 **미응답자 + 미희망자**에서 랜덤으로 차출합니다.
3. 관리자가 확정 명단을 자유롭게 수정하고, 카카오톡에 붙여넣을 수 있는 **텍스트 명단**을 복사합니다.

- 규모: 10~50명
- 접속 환경: 개인 휴대폰 + 일반 인터넷 (모바일 화면 기준으로 디자인)
- 추천 기술: **Next.js + Supabase(데이터베이스) + Vercel(배포)**. 사용자는 GitHub와 Vercel을 이미 사용 중입니다. 더 나은 대안이 있으면 이유와 함께 제안해도 됩니다.
- 개인정보 원칙: **이름(또는 구분용 별명)과 비밀번호만** 저장합니다. 군번, 주민번호, 연락처 등은 받지 않습니다.

## 2. 사용자 역할

| 역할 | 설명 |
|---|---|
| 일반 인원 | 로그인, 희망/미희망 표시, 본인 휴가·부상 입력·삭제, 결과 열람 |
| 관리자 | 일반 인원 기능 전부 + 명단 수정, 인원 관리, 근무일 수정, 관리자 지정, 변경 이력 열람 |

- **관리자도 일반 인원처럼 추첨 대상**입니다.
- 관리자는 **여러 명**이 될 수 있습니다. 관리자가 다른 인원을 "관리자로 지정"할 수 있고(본인은 관리자로 유지), 본인 권한은 "내려놓기" 버튼으로 내려놓습니다.
- **마지막 관리자 1명은 권한을 내려놓을 수 없습니다.** (관리자 0명 방지)
- 권한 변경(지정/해제)은 확인창("정말 진행하시겠어요?")을 거치고 변경 이력에 남깁니다.
- **비상 복구**: 관리자가 모두 로그인 불가 상태가 될 때를 대비해, 서버 환경변수(`EMERGENCY_KEY` 등)를 이용한 비상 관리자 복구 수단을 하나 둡니다. 화면에 노출하지 않습니다.

## 3. 인원 관리 및 로그인

- 로그인: **이름 + 비밀번호**. 동명이인은 "홍길동A/홍길동B"처럼 **표시 이름이 겹치지 않게** 등록합니다.
- **일괄 등록 도구**: 사용자가 준비한 목록(CSV/엑셀)으로 한 번에 등록합니다.
  - 열: `이름`, `초기비밀번호`, `진료반 여부`, `관리자 여부`
  - 초기 비밀번호를 비워 두면 무작위 4~6자리 번호를 자동 생성해 결과 파일로 내려줍니다.
- 비밀번호는 **해시(복원 불가능한 암호화)** 로만 저장합니다. 원문은 절대 저장하지 않습니다.
- **첫 로그인 시 비밀번호 변경을 강제**합니다.
- 로그인 시도 제한(연속 실패 시 잠시 차단)을 넣습니다.
- 관리자 인원 관리 기능:
  - 인원 추가 (이름 + 초기 비밀번호)
  - **비활성화** (전출·전역자: 삭제하지 않음. 로그인과 추첨에서만 빠지고 과거 명단·이력은 유지)
  - 진료반 여부 변경
  - 비밀번호 초기화 (새 초기 비밀번호 발급 후 다시 첫 로그인 변경 강제)
  - 관리자 지정 / 내려놓기

## 4. 근무일

- **주말(토·일)은 계산으로 자동 생성**합니다.
- **한국 공휴일**은 사이트에 **내장 목록**으로 넣습니다. 설·추석 연휴, 대체공휴일, 임시공휴일(발표된 것)을 포함합니다.
  - 외부 서비스에 접속하지 않고 코드/데이터에 내장합니다. (부대 네트워크와 무관하게 안정적)
  - 올해와 내년 목록을 넣되, **공식 자료(정부/천문연구원 등)와 대조해 검증하는 단계를 반드시 거칩니다.** 기억에 의존해서 날짜를 적지 않습니다.
  - 연 단위 갱신 방법을 README에 적어 줍니다.
- 화면에는 오늘부터 **약 60일 앞**까지의 근무일을 보여줍니다.
- 관리자 수정 기능 (**관리자 설정이 자동 생성 결과보다 우선**):
  - 근무일 **추가** (임시공휴일, 평일 출근 등)
  - 근무일 **삭제** (자동 생성된 날 중 근무가 없는 날)
  - 특정 날짜만 **동별 인원 수 다르게 설정**

## 5. 투표와 상태

### 5-1. 투표 기간
- 근무일 **30일 전 00:00(KST)** 에 열리고, **2일 전 오후 9시(21:00 KST)** 에 자동 마감합니다.
  - 예: 10/12(일) 근무 → 9/12부터 투표 가능, 10/10(금) 21:00 마감
- 열림/마감은 **현재 시각을 계산해서 버튼을 켜고 끄는 방식**으로 처리합니다. 서버가 따로 돌 필요가 없습니다.
- **모든 시각 계산은 한국 시간(Asia/Seoul) 기준**입니다. 서버 기본값은 UTC이므로 시간대 오류를 특히 조심하고, 테스트로 검증합니다.
- 마감 전에는 자유롭게 희망 ↔ 미희망을 바꾸거나 취소할 수 있습니다. 마감 후 인원 본인의 변경은 불가합니다.

### 5-2. 근무일별 개인 상태 4가지
| 상태 | 의미 | 추첨에서 |
|---|---|---|
| 희망 | 지원 버튼을 누른 사람 | 우선 대상 |
| 미희망 | "이날은 어려워요" 버튼을 누른 사람 | 부족할 때 차출 풀에 포함 (불이익·이득 없음, 의사 표시용) |
| 제외 | 휴가·부상 기간에 그 근무일이 걸친 사람 | 어떤 풀에도 들어가지 않음 |
| 미응답 | 위 셋 중 어디에도 해당하지 않는 사람 | 부족할 때 차출 풀에 포함 |

### 5-3. 휴가·부상(제외) 입력
- **본인 또는 관리자**가 시작일~종료일을 입력합니다. **승인 절차 없이 입력 즉시 제외**됩니다.
- 근무일이 제외 기간에 **하루라도 걸치면** 그 근무일에서 제외됩니다.
- 이미 "희망"으로 신청한 근무일에 제외 기간이 겹치면 **그 지원은 자동 취소**됩니다.
- 본인은 자기 기록을, 관리자는 모든 기록을 삭제할 수 있습니다.
- 입력자(본인/관리자)를 기록에 남깁니다.

### 5-4. 미응답자 표시
- 근무일 화면 **최상단에 주황색**으로 "아직 응답하지 않은 사람" 목록을 보여줍니다.
- 대상: 해당 근무일에 희망·미희망 표시도 안 했고, 제외도 아닌 활성 인원.
- 누군가 응답하면 목록에서 바로 빠집니다.

## 6. 추첨 규칙

하루의 근무에는 **두 개의 독립된 추첨**이 있습니다. 완전히 분리되어 서로의 풀에 영향을 주지 않습니다.

### 6-1. 진료실 추첨 (진료반 전용)
- 대상: **진료반 인원(현재 6명)** 만. 활성 상태이고 제외가 아닌 사람.
- 필요 인원: **2명** (설정에서 변경 가능)
- 진료반은 진료실 추첨에만 들어갑니다. 뽑히지 않은 진료반 인원은 그날 일반 추첨에 들어가지 않고 쉽니다.

### 6-2. 일반 추첨 (진료반을 제외한 나머지)
- 대상: 진료반이 아닌 활성 인원 (관리자 포함)
- 필요 인원: 동별 합계 **15명**

| 동 | 기본 인원 |
|---|---|
| 관리 1동 | 1 |
| 관리 2동 | 3 |
| 관리 3동 | 4 |
| 훈련동 | 4 |
| 종모견동 | 2 |
| 분만실 | 1 |

- 동 이름과 인원은 **설정 화면에서 바꿀 수 있게** 합니다. 코드에 고정하지 않습니다. 날짜별 override도 지원합니다(4장).

### 6-3. 추첨 절차 (진료실·일반 공통)
1. **희망자 수 ≥ 필요 인원**: 희망자끼리 랜덤으로 필요한 수만큼 뽑습니다. 끝.
2. **희망자 수 < 필요 인원**: 희망자는 **전원 확정**입니다. 남은 자리는 **미응답자 + 미희망자를 하나의 풀**로 합쳐 **동일 확률**로 랜덤 차출합니다. 제외자는 풀에 넣지 않습니다.
3. 결과에는 **"희망 확정 / 차출"** 구분을 표시합니다.
4. 풀 전체가 필요 인원보다 적어서 자리를 못 채우면, 채운 만큼만 확정하고 **"인원 부족 N명"** 을 관리자에게 눈에 띄게 알립니다.

### 6-4. 동 배정 (일반 추첨 15명)
- 15명이 확정되면 6개 동의 정원에 맞춰 **완전 랜덤으로 배정**합니다.
- 희망 여부는 동 배정에 영향을 주지 않습니다.

### 6-5. 랜덤과 신뢰성
- 단순 랜덤이면 충분합니다(과거 근무 횟수 반영 등 공정성 보정은 이번 범위에 없음).
- 난수는 서버에서 생성하고, 추첨 결과는 저장합니다. **한 근무일에 추첨은 한 번만 실행**되도록 데이터베이스에서 중복을 막습니다(같은 결과를 두 번 뽑지 않게).

## 7. 자동 추첨 실행

- 마감(2일 전 21:00 KST) 시각이 지난 근무일 중 **아직 추첨하지 않은 날**을 찾아 추첨합니다.
- 다음 세 가지를 겹쳐서 씁니다.
  1. **정기 실행(크론)**: Vercel Cron이 매일 밤 9시 무렵(KST) 서버 함수를 호출합니다. 무료 플랜은 하루 1회이고 실행 시각이 몇십 분 어긋날 수 있습니다. 이 제약을 사용자에게 설명해 주세요.
  2. **안전장치**: 마감 후 누군가 사이트에 접속했는데 추첨이 안 되어 있으면 그때 실행합니다(중복 실행 방지 필수).
  3. **관리자 수동 추첨 버튼**: 예비용입니다.
- 크론 호출 주소는 비밀 값(`CRON_SECRET` 등)으로 보호해서 외부에서 임의로 호출하지 못하게 합니다.
- 추첨은 여러 번 호출되어도 결과가 한 번만 만들어지는 **멱등성**을 갖게 합니다.

## 8. 확정 명단과 관리자 수정

- 추첨이 끝나면 근무일별 명단이 생기고, 각 이름 옆에 **희망 확정 / 차출 / 관리자 수정** 꼬리표를 붙입니다.
- 관리자는 명단에서 **삭제, 추가, 교체**를 자유롭게 할 수 있습니다(당첨자에게 사정이 생기는 경우 등의 처리 수단).
  - 후보 선택 시 제외(휴가·부상) 상태인 사람은 **경고만 띄우고** 넣을 수는 있게 합니다.
- **변경 이력**을 남깁니다: 누가, 언제, 무엇을 어떻게 바꿨는지(명단 교체, 관리자 지정, 인원 비활성화 등).
- 수정 결과는 일반 인원 화면에도 그대로 반영됩니다.

### 카카오톡용 텍스트 복사
"복사" 버튼 한 번으로 아래 형식이 클립보드에 복사됩니다. 이름은 예시입니다.

```
[10/12(일) 근무 명단]
■ 진료실 (2명)
- 홍길동
- 김철수
■ 관리 1동 (1명)
- 이영희
■ 관리 2동 (3명)
- ...
■ 관리 3동 (4명)
- ...
■ 훈련동 (4명)
- ...
■ 종모견동 (2명)
- ...
■ 분만실 (1명)
- ...
```

- 표 이미지 저장, 엑셀 내보내기는 이번 범위에 없습니다(나중에 추가 가능).

## 9. 제작 순서 (한 단계씩)

1. **준비**: Supabase 계정과 새 프로젝트 만들기, GitHub 저장소 연결, 프로젝트 뼈대 생성, `.env`와 `.gitignore` 설정
2. **데이터 창고 설계**: 표 만들기 — 인원, 제외 기간, 근무일, 희망/미희망 응답, 추첨 결과(동 배정 포함), 설정(동 이름·인원), 변경 이력
3. **로그인과 인원 일괄 등록**: 이름+비밀번호 로그인, 해시 저장, 첫 로그인 비밀번호 변경, CSV 일괄 등록 도구
4. **근무일 자동 생성**: 주말 + 한국 공휴일 내장 목록(공식 자료로 검증), 관리자 추가·삭제
5. **투표 화면**: 희망/미희망/휴가·부상 입력, 주황색 미응답 목록, 30일 전 오픈·2일 전 21:00 마감(KST)
6. **추첨 기능**: 진료실 + 일반 추첨, 동 배정, 중복 실행 방지
7. **관리자 화면**: 명단 수정, 관리자 지정/내려놓기, 인원 관리, 변경 이력
8. **텍스트 복사, 자동 추첨 예약**: 카톡용 복사 버튼, Vercel Cron, 접속 시 안전장치, 수동 버튼
9. **테스트와 배포**: 가짜 인원으로 아래 체크리스트 검증 → Vercel 배포 → 실제 명단 등록

## 10. 테스트 체크리스트 (9단계에서 반드시 확인)

- 희망자 > 필요 인원 / = / < 인 경우 각각 규칙대로 뽑히는지
- 제외자가 어떤 풀에도 들어가지 않는지 (휴가 기간 경계일 포함)
- 희망 신청 후 휴가를 입력하면 지원이 자동 취소되는지
- 진료반이 일반 추첨에 들어가지 않고, 진료실은 진료반에서만 뽑히는지
- 풀 전체가 부족할 때 "인원 부족" 알림이 뜨는지
- 15명이 동 정원(1·3·4·4·2·1)대로 배정되는지
- 마감 시각 경계(2일 전 20:59 / 21:01, 한국 시간)와 30일 전 오픈 시점
- 같은 근무일에 추첨을 두 번 호출해도 결과가 한 번만 생기는지
- 일반 인원이 관리자 화면·기능에 접근할 수 없는지
- 마지막 관리자가 권한을 내려놓을 수 없는지
- 비활성화한 인원이 로그인·추첨에서 빠지고 과거 명단에는 남는지
- 휴대폰 화면에서 주황색 미응답 목록과 명단이 잘 보이는지
