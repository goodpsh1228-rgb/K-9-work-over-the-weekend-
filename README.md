## 8단계: 카카오톡 복사 · 자동 추첨

- **카카오톡용 명단 복사** (관리자, 추첨이 끝난 근무일 화면): 버튼 한 번으로 아래 형식이 복사됩니다. 같은 투표 주에
  추첨된 날이 여러 개면 **이번 투표 주 전체 복사** 버튼도 나옵니다.
  ```
  [10/3(토) 근무 명단]
  ■ 진료실 (2명)
  - 홍길동
  ■ 관리 1동 (1명)
  - 이영희
  ```
- **자동 추첨** — 마감된 근무일(오늘 이후) 중 아직 추첨하지 않은 날을 찾아 추첨합니다. 세 겹으로 동작합니다.
  1. **정기 실행(Vercel Cron)**: `vercel.json` 에 매일 UTC 12시(= 한국 21:00~21:59 사이) 실행으로 등록.
     무료(Hobby) 플랜은 **하루 1번**, 그리고 **정한 시각의 1시간 안 아무 때나** 실행됩니다.
  2. **접속 시 안전장치**: 누군가 홈이나 근무일 화면을 열 때, 마감됐는데 추첨 안 된 날이 있으면 그때 추첨합니다.
     → 실제로는 마감(화·수 21:00) 뒤 **처음 사이트를 연 사람** 때 추첨되는 경우가 많습니다.
  3. **관리자 수동 버튼**: 근무일 화면의 "지금 추첨" (예비용)
  - 여러 번·동시에 불려도 날짜마다 결과는 하나만 저장됩니다.
- 자동 추첨 주소 `/api/cron/draw` 는 **`CRON_SECRET` 환경변수**가 있어야 동작하고, 그 값을 모르는 호출은 거부합니다.
- 투표 기간이 이미 끝난 날을 공휴일로 추가하면 곧바로 자동 추첨(전원 차출)됩니다.

## 6단계: 추첨 기능

> ⚠️ **추가 SQL**: `supabase/migrations/0003_record_draw.sql` 을 SQL Editor에서 한 번 실행하세요. (`/status` 의 "6단계 추가 SQL (0003)" 이 정상이면 적용됨)

추첨 규칙 (`src/lib/draw.ts`)
- **진료실(진료반)** 과 **일반** 은 따로 추첨합니다. 희망하지 않은 진료반은 진료실 차출에만 들어가고, 일반 동으로 차출되지 않습니다.
- **진료반은 희망할 때 다른 동도 고를 수 있습니다.** 그 동의 희망자로 일반 인원과 같은 조건으로 뽑히고, 그날 진료실 차출에서는 빠집니다.
- 동마다: 희망자 ≥ 정원이면 희망자 중 랜덤으로 정원만큼 **희망 확정**, 떨어진 희망자는 **그날 쉼**.
  희망자 < 정원이면 희망자 전원 **희망 확정**.
- 남은 빈자리: **미응답 + 미희망** 인원을 같은 확률로 **차출**해서, 빈자리가 있는 동에 **랜덤으로** 넣습니다.
  (희망했던 사람은 차출하지 않고, 휴가·부상 제외자는 어떤 풀에도 들어가지 않습니다.)
- 그래도 모자라면 채운 만큼만 확정하고 관리자에게 **인원 부족 N명** 을 빨간색으로 알립니다.
- 난수는 서버의 암호학적 난수를 씁니다. 한 근무일의 추첨은 데이터베이스가 **딱 한 번만** 저장합니다 (동시에 여러 번 눌러도 결과 하나).

화면
- 추첨이 끝난 날은 근무일 화면 맨 위에 "○○ 님은 △△ 출근입니다"와 **확정 명단**(희망 확정 / 차출 꼬리표)이 나옵니다.
- 관리자: 마감이 지난 날에 **지금 추첨** 버튼 (8단계에서 자동 추첨이 붙으면 예비용). 투표 중에는 **추첨 미리보기**(저장 안 됨).

## 5단계: 투표 화면

> ⚠️ 이 단계부터 **추가 SQL** 이 있습니다: `supabase/migrations/0002_response_post.sql` 을 SQL Editor에서 한 번 실행하세요.
> `/status` 화면의 "5단계 추가 SQL (0002)" 줄이 **정상**이면 적용된 것입니다.

- 홈의 근무일을 누르면 그날의 투표 화면(`/day/날짜`)으로 갑니다.
- **맨 위 주황색**: 아직 응답하지 않은 사람 (활성 인원 중 희망·미희망 표시가 없고, 휴가·부상 제외도 아닌 사람)
- **희망**: 원하는 **동을 골라서** 희망합니다. 진료반은 진료실로 희망합니다.
- **이날은 어려워요(미희망)** / **응답 취소** 가능. 투표 기간 안에서는 자유롭게 바꿀 수 있습니다.
- **희망 현황**: 진료실·각 동마다 `희망 인원 / 정원` 과 희망자 이름. 정원을 넘으면 빨간색 "(초과)".
- **투표 일정 (주간, 한국 시간)** — `src/lib/voting.ts`
  - 기본: **월 00:00 ~ 수 21:00**. 대상 = 그 주 토·일 + 다음 주 월~목 공휴일
  - 그 주 **금요일이 공휴일**(근무일)이면: **월 00:00 ~ 화 21:00**. 대상 = 그 주 금·토·일 + 다음 주 월~목 공휴일
  - **월요일은 상병·병장만**, 화요일부터 일병·이병(계급 미지정 포함)도 투표
  - 기간 밖에는 버튼이 사라지고, 서버도 거부합니다.
- **휴가·부상 입력**(`/absences`): 시작일~종료일(양 끝 포함). 입력 즉시 제외되고, 그 기간 근무일의 "희망"은 자동 취소됩니다.
  관리자는 다른 인원 것을 대신 입력하거나 삭제할 수 있고, 입력자가 기록됩니다.

## 4단계: 근무일 자동 생성

- **토·일요일**은 계산으로, **공휴일**은 내장 목록(`src/lib/holidays.ts`)으로 자동으로 근무일이 됩니다.
- 모든 날짜 계산은 **한국 시간(KST)** 기준입니다 (`src/lib/kst.ts`).
- 홈 화면에 오늘부터 **60일 앞**까지의 근무일이 보입니다.
- 관리자 메뉴 → **공휴일 추가**(`/admin/duty-days`)
  - 근무일 **추가** (평일 출근, 발표된 임시공휴일 등) / **근무 없음**(삭제) / **되돌리기**
  - 날짜를 누르면 **그날만 자리별 인원**을 다르게 설정
  - 관리자 설정이 자동 계산보다 우선합니다. 추첨이 끝난 날은 삭제·인원 변경이 막힙니다.

### 공휴일 목록 갱신 (매년 1번)

현재 목록: **2026년 ~ 2027년** (2026-09-29 검증)

매년 6월 무렵 우주항공청이 **다음 해 「월력요항」**을 발표합니다. 발표 후에 다음처럼 갱신합니다.
1. [천문우주지식정보 월력요항](https://astro.kasi.re.kr/life/post/almanac) 또는 우주항공청 보도자료에서 다음 해 공휴일 표를 확인합니다.
2. `src/lib/holidays.ts` 의 `HOLIDAYS` 에 `"YYYY-MM-DD": "이름",` 형식으로 다음 해 날짜를 모두 추가합니다. (설·추석 연휴 3일, 대체공휴일, 선거일 포함)
3. 같은 파일의 `HOLIDAYS_LAST_YEAR` 숫자를 그 해로 바꿉니다.
4. 파일 위쪽 "검증 기록"에 날짜와 자료 출처를 적습니다.
5. 발표된 공휴일 개수(월력요항의 "공휴일 ○일")와 목록 개수가 맞는지 대조합니다.

> Claude Code에게 "내년 공휴일 목록 갱신해줘"라고 요청해도 됩니다.
> 목록이 부족하면 근무일 관리 화면에 주황색 알림이 뜹니다. 갑자기 발표된 **임시공휴일**은 목록을 고치지 않고 "근무일 추가"로 바로 넣을 수 있습니다.

## 3단계: 로그인과 인원 일괄 등록

| 주소 | 화면 | 누가 |
|---|---|---|
| `/login` | 이름 + 비밀번호 로그인 | 모두 |
| `/change-password` | 비밀번호 변경 (첫 로그인 때 강제) | 로그인한 인원 |
| `/home` | 로그인 후 첫 화면 (5단계에서 투표 화면이 됨) | 로그인한 인원 |
| `/admin/members/import` | 인원 일괄 등록 | 관리자 |
| `/status` | 서버 점검 화면 | 모두 (비밀 값은 보이지 않음) |
| `/emergency` | 비상 관리자 복구 (링크 없음, 주소를 아는 사람만) | `EMERGENCY_KEY` 를 아는 사람 |

규칙
- 비밀번호는 해시로만 저장하고, 새 비밀번호는 6자 이상입니다.
- 비밀번호를 5번 연속 틀리면 그 이름은 10분 동안 로그인이 차단됩니다.
- 일괄 등록 때 초기 비밀번호를 비우면 **1111** 로 등록됩니다. 첫 로그인 때 각자 새 비밀번호(6자 이상)로 바꿔야 다른 화면을 쓸 수 있습니다.
- 비밀번호를 바꾸면 다른 기기의 로그인은 자동으로 풀립니다.

### 첫 관리자 만들기
1. Vercel → Settings → Environment Variables 에 `EMERGENCY_KEY` 추가 (Secret, 본인이 정한 16자 이상 문장) → Redeploy
2. 사이트 주소 뒤에 `/emergency` 를 붙여 접속 → 비상 키, 관리자 이름, 비밀번호 입력
3. `/login` 에서 로그인 → 홈의 "인원 일괄 등록"에서 인원 등록

| `posts` | 근무 자리 설정 (진료실 2 / 관리1동 1 / 관리2동 3 / 관리3동 4 / 훈련동 4 / 종모견동 2 / 분만실 1) |
| `duty_day_overrides` | 근무일 수동 추가·삭제 |
| `duty_day_post_counts` | 특정 날짜만 자리별 인원 변경 |
| `responses` | 희망 / 미희망 응답 |
| `absences` | 휴가·부상(제외) 기간 |
| `draws` | 추첨 실행 기록 (근무일당 1번만 가능) |
| `assignments` | 확정 명단 (희망 확정 / 차출 / 관리자 수정) |
| `audit_logs` | 변경 이력 |

실행 방법:
1. GitHub에서 `supabase/migrations/0001_init.sql` 파일을 열고, 오른쪽 위 **복사 버튼(Copy raw file)** 을 누릅니다.
2. Supabase 대시보드 → 왼쪽 **SQL Editor** → 빈 편집창에 붙여넣기 → **Run**.
3. "Success. No rows returned" 가 나오면 성공. 사이트 점검 화면의 4번째 줄이 **정상**이 됩니다.

> 이 SQL은 **한 번만** 실행합니다. 두 번 실행하면 "already exists(이미 있음)" 오류가 나는데, 이미 만들어졌다는 뜻이므로 괜찮습니다.

## 1단계: 아이패드(또는 컴퓨터 없이)로 확인하기 — Vercel 사용

아이패드에서는 프로그램을 직접 실행할 수 없으므로, Vercel이 GitHub 코드를 받아 인터넷에 띄워 주는 방식으로 확인합니다.

1. <https://vercel.com> 에서 **Add New… → Project**를 누르고, 이 저장소를 **Import** 합니다.
2. 설정 화면에서 **Environment Variables**를 펼쳐 아래 2개를 입력합니다.
   - `SUPABASE_URL` = Supabase의 Project URL
   - `SUPABASE_SECRET_KEY` = Supabase의 Secret key (`sb_secret_...`)
3. **Deploy**를 누르고, 끝나면 나오는 주소(`https://….vercel.app`)를 엽니다.
4. 세 줄이 모두 **정상**이면 1단계 완료입니다.

> 환경변수를 나중에 바꾸면 **Deployments → 최근 배포의 ⋯ → Redeploy**를 해야 반영됩니다.
>
> Vercel 무료(Hobby) 플랜은 비공개 저장소에서 **계정 주인이 작성한 커밋만 자동 배포**합니다.
> 그래서 이 저장소의 커밋 작성자는 저장소 주인 계정으로 설정되어 있습니다.

## 1단계: 내 컴퓨터에서 실행하기

### 준비물
- [Node.js](https://nodejs.org/) 20 이상 (LTS 버전 권장)
- Git

### 순서
```bash
# 1) 저장소 내려받기 (이미 받았다면 생략)
git clone https://github.com/goodpsh1228-rgb/K-9-work-over-the-weekend-.git
cd K-9-work-over-the-weekend-
```

> ⚠️ `.env.local` 에는 비밀 키가 들어갑니다. 이 파일은 `.gitignore` 에 의해 GitHub에 올라가지 않습니다.
